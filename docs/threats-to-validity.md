# Threats to validity

What limits the conclusions that can be drawn from the four evaluated rounds (rounds 1–4) and from the baselines. Most of the list appears in section 6 of the [paper](../paper/reversible-faces-benchmark-paper.md), which covers rounds 0–3 only; the points on round 4, on the validator, on the prompt's production note and on provider changes are added here. Where a limit belongs to an earlier version of the code, it is stated as historical and kept apart from what the current code does (see [Validator: historical limits, current capabilities and impact](#validator-historical-limits-current-capabilities-and-impact)).

- **The evaluation is not blind.** The evaluator opens files named after the model and prompt, so judgments are not blind to the generating model. Whether the evaluator read each model's declared `EVENT:`/`TITLE:` lines before judging was not recorded.
- **Evaluator conflict of interest.** The only judge is the benchmark's author, who also wrote every prompt after seeing earlier results. There is no blind protocol, no second rater and no agreement statistic.
- **Informal verdicts.** The verdict words ("OK", "somewhat bad", "low", ...) describe one person's reaction. They are not measurements and cannot be ranked reliably (see [`methodology.md`](methodology.md)).
- **Sample size.** Three models, one run per model per prompt (apart from retries after technical failures). Variance across runs is unknown.
- **Uneven comparisons.**
  - In round 1 the MiniMax output came from prompt v2 because its v3 run was interrupted.
  - In round 3, DeepSeek ran with reasoning disabled and MiniMax at low reasoning effort, while GLM used medium effort. DeepSeek's round 3 result is therefore **not comparable** with the other two.
  - Round 3 versus round 1 is a before/after comparison with several things changed at once, and the evaluator's expectations may also have changed.
- **Unverified prompt content.** Every prompt contains the same placeholder section (6b) with short text descriptions of two real Whistler drawings, written from public images and flagged inside the prompt as unverified. They are kept verbatim because the models saw them.
- **Round 4 (tool-enabled, post-paper) is uncontrolled.** Prompt v6 changed more than the tools: the unverified Whistler descriptions and the placeholder note were removed, the dictionary's frame wording was made precise, the title was changed to "OHO!", and Stage 2 now includes a render and a blind reading. The tool effect cannot be separated from these changes, and round 4 cannot be compared with round 3 without caveats.
- **MiniMax in round 4 is a selection.** Its first run spent its whole first turn reasoning and never called a tool; it was re-run once with a larger per-turn token limit (the only change), and the re-run is the reported result.
- **Providers and routing in round 4.** Providers were not pinned; DeepSeek was served by three providers over the turns of one run. DeepSeek again ran with reasoning disabled.
- **The harness gives its own feedback.** The diagnostics (symmetry number ρ, bounding boxes, element table) and the image the models see are produced by code written by the author, and a model may optimize for them rather than for the evaluator's judgment.
- **Humor is untested by design.** The evaluation of round 4 says the images do not convey a comic message; that is one person's reaction, and the prompt asks for a physical difference, not for a tested joke.
- **Harness safety and cost limits (round 4).** The round-4 harness (commit `6747499`) rendered untrusted SVG with Chrome `--no-sandbox` outside the sandbox and injected it into HTML after a regex clean-up. The delivered SVGs contain only plain drawing elements ([`validator-audit.md`](validator-audit.md)), so there is no sign that the results were affected, but equivalence with the current rendering path was assumed, not re-run, and the exposure existed; it is closed in the current harness ([`security.md`](security.md)). The US$0.25 cap in the round-4 harness was checked **only after each call, against the provider-reported cost** (there was no pre-call estimate; that was added in the hardening), so it was an approximate operational limit; billed-but-unreported failed requests can make real spend higher, so reported totals are lower bounds.
- **Rendering variance.** Previews, the harness's pictures and the numbers shown to the models (rho, bounding boxes) come from one Chrome version on one platform ([`reproduction.md`](reproduction.md)); other browsers may differ slightly. Judgments are made on the SVG itself.
- **Protocol is not identical across rounds.** Rounds 0–3 are one-shot without tools; round 4 is a single-attempt tool-augmented run with harness messages. Do not pool or rank them (see the protocol wording in [`methodology.md`](methodology.md)).
- **Production note and legal assertion inside the prompts.** The prompts v1–v5 say "[PLACEHOLDER — Cláudio to add and verify.]" and call the two Whistler drawings "public domain" (unverified). The models read both, so they are part of the stimulus and a possible confound; the text is kept verbatim. Prompt v6 (round 4) removed both.
- **Frame wording in the prompts.** The prompts v1–v5 state the dictionary as "a feature of B at height −y (as seen on the page)", which is looser than the docs' "B's own frame"; a model could have been misled by it.
- **The file validator never judges the drawing.** It checks the file contract (structure and safety). Passing it says nothing about whether a drawing is a good reversible face. Its history is in the section below: an earlier version also missed parts of the contract, which the current version does not.
- **Events and recency.** The models had no search, so the "recent event" depends on training data; several chose events from 2023–2025. Declared events and figures (for example market-value drops) are model wording and are not fact-checked.
- **Heuristic geometry.** The canon, the tolerance and the dictionary are design conventions, not validated perceptual facts. The dictionary is not a partition of strokes.
- **Scope of the informal claim.** The statement that diffusion image models rarely manage this task is an untested observation: diffusion models were **not** tested here.
- **Models and providers change.** Model names are OpenRouter ids at the time; providers may change or retire them, and provider-side behavior (reasoning limits that were not enforced, timeouts) affected some runs.


## What the results measure: capability, reliability and efficiency

A single output per model and condition mixes three different things that should not be read as one capability.

| Dimension | Question | What the repository can say |
|---|---|---|
| **Capability** | Can the model build a reversible figure at all? | A single delivered, human-approved output shows that it *can*, under that prompt and setting. Nothing more. |
| **Reliability** | How often does it succeed under equivalent conditions? | Unknown. One run per model per prompt (apart from retries after technical failures); no repeats, no variance estimate. |
| **Efficiency** | How many tokens, calls, renders and dollars does it need? | Recorded per run (round `logs/` and `EVALUATION.md`), but settings differ between models and rounds, so costs are not comparable. |

- **Token exhaustion is a task-completion failure, not geometric incapacity.** In round 3, DeepSeek with reasoning on kept re-verifying its geometry until the token limit and delivered no SVG in four configurations. That shows a problem completing the task under that inference regime. It does not show that the model cannot do the geometry: with reasoning disabled the same model delivered an SVG that the evaluator judged identifiable in both orientations. The two results are also not comparable with the other models' (different settings).
- **The cost budget is not a hard financial limit.** The US$0.25 cap in the round-4 harness is an operational limit, checked after each call against the provider-reported cost (the current harness also estimates the worst case before each call). Failed or timed-out requests can be billed without being reported, and estimated prices can differ from real ones, so reported totals are lower bounds ([`reproduction.md`](reproduction.md)).
- **Round 4 ran before the renderer hardening.** The round-4 outputs were produced by the harness of commit `6747499` and were not regenerated with the current, hardened harness ([`security.md`](security.md)). The prompts, tools, limits and settings are the same; what changed is how untrusted SVG is parsed and rendered, the addition of a pre-call cost estimate, logging and overwrite protection.

## Validator: historical limits, current capabilities and impact

**Historical (the validator of commit `6747499`, used when the rounds were run).** It checked size, XML well-formedness, the SVG namespace, the presence of a `viewBox` and of `width`/`height`, and a list of forbidden elements. It did **not** check the values of `width` and `height` and did **not** reject external references or several unsafe constructs. Run on the 30 deliberately invalid fixtures in `tests/fixtures/invalid/`, it accepted 18 of them, including the three cases raised by the external review: `<use href="https://...">`, `width="12" height="23"` and SVG animation ([`validator-audit.md`](validator-audit.md)). In addition, the runner of that time injected `viewBox`/`width`/`height` itself, so those attributes were rarely a problem in practice.

**Current (`scripts/validate_svg.py`, version 2.1.0).** It enforces the file contract exactly: size at most 300 KB; valid XML with no DTD or entity declaration; root `<svg>` in the SVG namespace; `viewBox` exactly `0 0 1000 1000`; `width` and `height` exactly `1000`; no `<text>`, `<image>`, `<foreignObject>`, `<script>`, gradients or filters; no animation; no event attributes; no external reference of any kind (`href`/`xlink:href` other than `#id` on `<use>`, `url()` other than `url(#id)`, `@import`, `javascript:`/`data:` values, CSS escapes); no unknown elements, excessive size or depth, `<use>` cycles or expansion bombs. It rejects all 30 invalid fixtures, each for the expected reason (`tests/test_validate_svg.py`). It reports `<title>`/`<desc>`, `<metadata>`, a `<style>` element and unknown attributes as warnings. It still checks structure and safety only: it does not judge how the drawing looks.

**Impact on the published results: none.** The validator is a tool, not part of the data. Every one of the 18 SVG files under `rounds/*/svg/` and `rounds/*/not-evaluated/` passes the current validator with no error, including the 12 evaluated ones; the three round-2 files carry only `<title>`/`<desc>` warnings ([`validator-audit.md`](validator-audit.md)). The verdicts were made by a human looking at the SVG, not by the validator. No existing file was modified.


## Baselines (added after round 4)

The 15 comparison runs in [`../baselines/`](../baselines/README.md) add their own threats: a judge model, David (Peter's Hermes agent), that is text-only and works from a vision describer that sometimes invents the expected second face; a second stage that is not fully blind to the rotation; one call per cell; a 0-2 rubric that is the operationalisation, by Peter Weyland (Claudio's Grok Bot assistant), of the prompt's gates and was scored non-blind; image generators given a different prompt from the text models; GLM 5.3 Max not one-shot. See the caveats at the top of that page.
